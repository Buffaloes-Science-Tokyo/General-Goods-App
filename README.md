# グッズ物販レジ

グッズ販売用の Web アプリです。オフラインでもレジ操作ができ、オンラインに戻ると自動でクラウド（Neon）と同期します。複数台で同時に使えます。

- **レジ**：商品をタップして会計。割引の自動適用（その会計だけ外すことも可）、レジで選ぶ割引、手入力の値引き（円／%）、現金（お釣り計算）とキャッシュレス。
- **オンライン**：BASE・BOOTH などオンラインショップの注文の記録（送料・手数料・発送の実費つき）、未発送／発送済の管理、キャンセル、CSV 出力。在庫は店頭と共通。
- **割引**：商品割引・まとめ買い・会計割引のルール作成、有効期間、自動／レジで選択、利用実績。
- **商品・在庫・価格**：商品の登録・編集（タイプ・サイズつき。「別サイズ・タイプを追加」で内容を引き継いで登録）、販売価格、平均原価と粗利率、入荷（仕入単価つき）・原価修正、在庫の履歴、CSV 出力。
- **棚卸し**：在庫を持っていく先（物販の会場など）を「棚卸しハブ」として追加・編集し、ハブごとに持っていく数を記録（持ち出し数・売れた数・残りを表示、売れた数のリセット）。おおもとの在庫は「ベース」で、変更できません。ベース・ハブごとに、現金とキャッシュレスの売上を会計アプリのどのプールに反映するかも選べます。入荷・在庫調整の記録の一覧もここにあります。
- **レジのハブ選択**：レジの上部でハブを選ぶと、そのハブに持ち出した商品だけを表示し、持ち出し分の残りを超えては売れません。ハブの選択は端末ごとで、会場の端末とお店の端末で別々に使えます。
- **入荷・在庫調整の訂正**：間違えた入荷・在庫調整・原価修正は、在庫の履歴の「修正」で正しい数・単価に直すか、「取消」で無かったことにできます。在庫数と平均原価は自動で計算し直します。記録は消さずに「取り消し」「修正後」の記録を追加するので、他の端末にも正しく同期されます。
- **販売履歴**：店頭／オンライン・日付での絞り込み、伝票の詳細（割引の内訳つき）、取引の取り消し（在庫も戻る）、CSV 出力。
- **ダッシュボード**：店頭／オンラインの切り替え、販売先（店頭・ショップ別）の内訳、売上・粗利・取引数・客単価・販売点数（前の期間との比較つき）、売上の推移、支払い方法、商品ランキング（売上・粗利・数量）、カテゴリ別・タイプ別・サイズ別、割引の実績、時間帯別、在庫アラート。
- **売上報告書（PowerPoint）**：ダッシュボードの「報告書(pptx)」から、開始日・終了日と対象（店頭／オンライン）を選んで .pptx を作成。表紙・サマリー（同じ日数の前期間との比較）・売上の推移・商品ランキング・売上の内訳（カテゴリ・販売先・支払い方法）・時間帯別・割引の実績・在庫アラートのスライドが入ります。ファイルは端末内で作成します（作成用の部品は初回に読み込み、以降はオフラインでも作成できます）。
- **ホームとログイン**：起動するとホーム画面に「レジアプリ」と「会計アプリ」が並びます。選ぶとそのアプリのパスワードを聞かれます（レジと会計でパスワードは別。どちらも全端末で共通）。一度ログインすれば、ログアウトするかパスワードが変更されるまでオフラインでも使えます。
- **会計アプリ**
  - **収支の記録**：会場費・交通費などの経費や、レジ以外の収入を日付・科目・プール・キャッシュフロー対応（相手名。キャッシュフローの相手が候補に出るが、無い名前も入力可）・金額・メモで記録（編集・削除、月・種類・プールでの絞り込み、CSV 出力）。プールで絞り込むと、そのプールに入るレジの売上・手数料も日ごとにまとめて表示します。
  - **キャッシュフロー**：お金の出入りを種類（支出／収入）・日付（1日、または開始日〜終了日の期間）・科目・相手・金額・メモで記録（期間の記録は、月で絞り込むとその月と重なるものを表示。編集・削除、月・種類・相手での絞り込み、相手ごとの合計、CSV 出力）。収支の記録とは別のもので、ダッシュボードやプールの収支には含めません。収支の記録と同じく、会計アプリでログインした端末にだけ同期されます。
  - **徴収返金管理**：キャッシュフローの相手と、収支の記録の「キャッシュフロー対応」に書いた相手名をもとに、対象名ごとに「必要な返金額（キャッシュフローの支出）と実際に支出した額（記録の支出）の差」「必要な徴収額（キャッシュフローの収入）と実際の収入額（記録の収入）の差」を表示（残りがあるものだけの表示、対象ごとの明細、CSV 出力）。
  - **プール**：手元の現金・口座など、お金の置き場所ごとのプールを追加・編集・削除し、プールごとの収支（全期間）を表示。レジの会計は、会計した時点のハブ（またはベース）の設定で反映先が決まり、伝票に記録されます（設定前の会計は今の設定に従います）。プールの一覧は全端末で共有されます。
  - **会計ダッシュボード**：期間（今月・先月・今年・全期間・期間指定）ごとの収入・支出・収支、収入と支出の科目別の内訳、プール別の収支、月別の収支、明細の CSV 出力。レジの売上（店頭・オンライン）、入荷した時点の仕入額（入荷の修正・取消を反映）、キャッシュレス決済の手数料、オンラインの手数料・発送の実費は自動で反映されます。
  - **シミュレーション**：在庫のある商品ごとに「売れる数」を入力すると、その場合の売上・粗利・販売点数・在庫に対する収支（手取り − 在庫の仕入額 − 仮の支出）・売れ残りと、商品別・カテゴリ別・支払い方法の内訳を表示。商品ごとに、今の在庫の仕入額を回収する（黒字になる）のに最低限必要な販売数と、在庫がすべて売れたときの粗利も表示します。店頭で定価で売る想定で、追加コスト（レジ）とキャッシュレス手数料（キャッシュレスの割合は店頭の実績が初期値）を引いて計算します。切り替えで「会計ダッシュボード（シミュレーション後）」も表示でき、今の実績にシミュレーションの売上・手数料（今日の日付）と、そこで仮に記録した支出（会場費など。会計の記録には残りません）を足した収支を、実績との差つきで表示します（売る場所のハブを選ぶと、その設定のプールに入れて計算）。入力はその端末に残ります。
  - 収支の記録は、会計アプリでログインした端末にだけ同期されます（レジだけログインした端末には送られません）。会計アプリだけログインした端末でも、ダッシュボードのためにレジのデータは同期されます。
- **設定**：同期の状態とログアウト、店名、端末コード、バックアップと復元、サンプルデータ。

## 仕組み

```
[端末A] ─┐                        ┌─ Neon (Postgres)
[端末B] ─┼─ POST /api/sync ──────┤
[スマホ] ─┘  (Vercel Functions)   └─ products / sales / stock_events / shop_settings
```

- どの操作もまず端末の IndexedDB に保存し、送信待ちキューに積みます。通信が無くてもレジは止まりません。
- オンラインになったとき、変更したとき、30 秒ごと、画面に戻ったときに自動で同期します。
- **在庫数は上書きせず「増減の記録」を同期して合計**します。2 台が同時に売っても在庫がずれません。
- 商品情報と店名は「最後に更新したものが勝ち」です。取消はどちらかの端末で取り消されていれば取消として扱います。
- 同じ記録を 2 回送っても重複しません（ID で判定）。
- Service Worker がアプリ本体をキャッシュするので、電波が無い状態でも起動できます（本番ビルドのみ）。
- 伝票番号は `端末コード-連番`（例 `A3-0012`）です。端末ごとに違うコードを設定してください。

## 商品の属性（タイプ・サイズ）

- タイプ（例：ブラック、通常版、キャラA）とサイズ（例：S / M / L / F）は任意の文字です。入力済みの値が候補に出ます。
- タイプ・サイズの組み合わせごとに 1 つの商品として登録します。在庫・価格・原価も組み合わせごとに管理します。
- 既存の商品の「編集」→「別サイズ・タイプを追加」で、商品名・カテゴリ・価格・原価を引き継いで登録できます。
- 商品名・タイプ・サイズがすべて同じ商品を保存しようとすると、確認のメッセージが出ます。
- サイズは XS → S → M → L → XL → … → F の順に並びます。数字のサイズは小さい順、それ以外は文字順です。

## オンラインショップの注文

- 「オンライン」タブの「＋ 注文を記録」で、ショップ名・注文番号・商品と数量・販売単価（店頭と違ってもよい）を入力します。
- 金額の考え方
  - **売上（お客様の支払額）** = 商品小計 − クーポン・値引き ＋ 送料（お客様から受け取った額）
  - **粗利** = 売上 − 原価（移動平均）− 販売・決済手数料 − 発送にかかった実費
  - 手数料は金額で入れるか、%を入れると支払額から計算します。
- 在庫は店頭と同じ在庫から減ります。すでに売れた注文を記録するため、在庫が足りなくても確認のうえ記録できます（在庫はマイナスになります）。
- 「発送済にする」で発送状況を管理します。未発送の件数と、いちばん古い未発送の注文はタブ上部に出ます。
- 記録後に変えられるのは、手数料・発送の実費・メモ・発送状況です。商品や数量を間違えたときは、注文をキャンセル（在庫が戻ります）して記録し直してください。
- 発送状況などの変更は他の端末にも同期されます。2台で同時に変えたときは、後から変えた方が残ります。キャンセルは、どちらかの端末でキャンセルしていればキャンセルになります。

## 会計手数料・追加コストと「最低額」

**設定**
- 設定タブの「会計手数料と最低粗利」で、次の3つを設定します（全端末で共有）。
  - キャッシュレス決済の手数料率
  - オンラインショップごとの手数料（% ＋ 注文ごとの固定額）
  - 割引しても最低限残す粗利（1点あたり 円 ＋ %）
- 商品の編集画面で、最悪の場合の追加コスト（1点あたり）を設定します。レジで売るとき（袋など）とオンラインで売るとき（梱包材など）で別々に入れます。

**最低額**
「最悪の場合でも粗利が最低粗利を下回らない価格」です。次の式で求めます。

```
最低額 = (平均原価 + 追加コスト + 固定手数料 + 最低粗利の円) ÷ (1 − 手数料率 − 最低粗利の%)
```

- レジ（キャッシュレス）で売る場合と、オンラインで売る場合の両方を計算し、高い方を採ります。
- オンラインは、登録したショップの中で一番高い手数料率と一番高い固定額を組み合わせ、1点だけの注文だった場合で計算します。

**表示される場所**
- 商品一覧：販売価格の下に「最低 ¥◯」を表示します。販売価格が下回っていれば赤になります。
- 割引の追加・編集：対象商品ごとに割引後の価格と最低額を並べ、「最大◯%／◯円まで」（N点で◯円なら「◯円以上」）を表示します。ボタンでその値に合わせられます。
- 最低額を下回る割引も、確認のうえ保存できます。割引一覧には「▲ ◯件の商品で最低額を下回ります」と表示します。
- チェックは割引1つごとに行います。他の割引と重なった場合は含みません。会計割引の円引きは、条件ぎりぎりの会計（条件なしなら1点だけの会計）に全額かかった場合で計算します。

**実際の粗利への反映**
- キャッシュレスの手数料は、会計のたびに金額を記録し、実際の粗利から引きます。
- オンラインの手数料は、注文の記録時にショップ名が一致すれば自動で入ります（手で直すこともできます）。
- 商品ごとの追加コストは「最悪の場合」の見積もりなので、最低額の計算にだけ使い、実際の粗利からは引きません。

## 割引

| 種類 | 例 | 対象 |
|---|---|---|
| 商品割引 | アパレル 10%オフ／1点200円引き | すべて・商品・カテゴリ・タイプ・サイズから選ぶ |
| まとめ買い | 缶バッジ 3個で1,200円／3点以上で10%オフ | 同上（対象の合計点数で判定） |
| 会計割引 | 5,000円以上で300円引き／SNSフォロー割 5% | お会計全体 |

- **適用のしかた**：「条件を満たしたら自動」か「レジで選んだときだけ」（SNS割・学割など）を選べます。レジでは、自動の割引を × でその会計だけ外せます。
- **有効期間**：開始・終了の日時を設定できます（イベント期間だけの割引など）。「停止」でいつでも止められます。
- **重なり方**
  1. 商品割引・まとめ買いは、1つの商品に1つだけ付きます。お客様に一番得なものから順に決めます。
  2. 会計割引は、1の割引を引いた後の金額で条件を判定し、一番得なもの1つだけ付きます。
  3. 手入力の値引き（円／%）は最後に引きます。
- 「N個で◯円」は、単価の高い商品から N 個ずつ組にします。割引額の1円未満は切り捨てます。
- 会計には割引の内訳が残ります。ダッシュボードの商品ランキングとカテゴリ別売上は、商品割引・まとめ買いを引いた金額で集計します。会計割引と手入力の値引きは、売上・粗利の合計にだけ反映します。
- 割引ルールも他の端末に同期されます。オフラインでも、端末に保存されているルールで計算します。

## 原価の考え方（移動平均法）

入荷のたびに仕入単価が変わっても、在庫全体の平均原価で粗利を計算します。

| 操作 | 在庫数 | 平均原価 |
|---|---|---|
| 入荷（仕入単価つき） | 増える | `(在庫 × 平均原価 + 入荷数 × 仕入単価) ÷ (在庫 + 入荷数)`。在庫が 0 以下だったときは仕入単価そのもの |
| 販売 | 減る | 変わらない。**売れた時点の平均原価**がその販売の原価になる |
| 棚卸し・取消 | 増減 | 変わらない |
| 原価修正 | 変わらない | 指定した値に置き換える（入力ミスの訂正用。過去の販売の粗利は変わらない） |

- 例：15 個（平均 ¥1,471）の在庫に、15 個を ¥1,700 で入荷 → 30 個・平均 ¥1,586
- 平均原価は、同期される在庫の記録（仕入単価を含む）を時刻順に計算し直して求めます（`src/costing.ts`）。オフラインの端末が後から入荷を同期しても、全端末で同じ結果になります。
- 商品登録時の「仕入単価」が最初の原価です。登録後の原価は、入荷か原価修正で変えます。

## ローカルで動かす

```bash
npm install
npm run dev
```

`.env` が無ければ、同期 API は組み込みの Postgres（PGlite、データは `.pglite/`）を使います。
この場合のログインパスワードは、レジが `dev`、会計アプリが `dev-accounting` です。同じ PC の別ブラウザや、同じ Wi-Fi のスマホ（`http://<PCのIP>:5173`）から開けば、複数台での同期を試せます。

Neon につないで試すときは `.env.example` を `.env` にコピーして値を入れてください。

## 本番に公開する（Neon + Vercel）

1. **Neon**：https://neon.tech でプロジェクトを作り、接続文字列（`postgresql://...`）をコピーします。テーブルは最初の同期のときに自動で作られます。
2. **Vercel**：このフォルダを GitHub に push し、Vercel で Import します（フレームワークは Vite が自動で選ばれます）。
3. Vercel の **Settings → Environment Variables** に次の 4 つを登録して、再デプロイします。
   - `DATABASE_URL`：Neon の接続文字列
   - `APP_PASSWORD`：レジアプリのログインに使うパスワード（推測されにくいものにしてください）
   - `ACCOUNTING_PASSWORD`：会計アプリのログインに使うパスワード（レジとは別のものにしてください）
   - `SYNC_TOKEN`：ログイン状態の署名に使う秘密の文字列（例：`openssl rand -hex 24` で作った文字列。端末で入力することはありません）
4. 各端末で公開 URL を開き、パスワードでログインします。
5. スマホやタブレットでは「ホーム画面に追加」すると、アプリのように全画面で使えます。

> DB の接続文字列はサーバー（Vercel）だけに置き、ブラウザには渡しません。端末にはパスワードそのものは保存せず、ログイン時に受け取ったトークンで API に接続します。
> `APP_PASSWORD` か `SYNC_TOKEN` を変えると、全端末がレジアプリからログアウトされます（未送信の変更は端末に残り、ログインし直すと送信されます）。

## 注意

- 在庫チェックは端末の手元のデータで行います。オフラインの端末が 2 台同時に最後の 1 個を売った場合は、同期後に在庫がマイナスになります（記録は残るので棚卸しで直せます）。
- 「この端末のデータを消去」は端末だけを消します。クラウドのデータは残り、次の同期で取り直します。送信待ちがある状態で消すと、その分は失われます。
